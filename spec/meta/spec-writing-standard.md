# Spec Writing Standard

Every mature spec must be written for both human understanding and AI retrieval.

## Required Metadata

Each spec should start with:

- Domain owner.
- Status.
- Last reviewed date.
- Upstream dependencies.
- Downstream dependencies.
- Related protocols.
- Related events.
- Related runtime systems.
- Related governance systems.
- Related observability systems.
- Semantic tags.
- Canonical references.

## Required Sections

Each domain spec should define:

- Purpose.
- Philosophy.
- Architecture.
- Primitives.
- Runtime semantics.
- Lifecycle.
- Protocols.
- Contracts.
- Event flows.
- State transitions.
- Orchestration behavior.
- Observability.
- Scalability.
- Governance.
- Security.
- Resilience.
- Replayability.
- Failure semantics.
- Extensibility.
- Implementation guidance.
- Future evolution strategy.

## Style Rules

- Prefer explicit boundaries over broad prose.
- Link related specs instead of duplicating definitions.
- Define canonical terms once and reference them through indexes.
- Mark assumptions as assumptions.
- Mark open research questions separately from accepted architecture.
- Avoid treating sample implementation details as permanent architecture.
