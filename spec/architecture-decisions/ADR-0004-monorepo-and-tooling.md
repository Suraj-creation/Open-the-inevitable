# ADR-0004: Monorepo Layout and Development Tooling

**Status:** Accepted
**Date:** 2026-06-02
**Related:** [ADR-0003](ADR-0003-tech-stack.md) (TypeScript-first + neutral JSON Schema)

## Context

Phase 1C scaffolds the executable substrate. ADR-0003 committed to TypeScript-first with
JSON Schema as the canonical contract form. This ADR pins the concrete monorepo tooling so every
package is built, typed, tested, linted, and verified consistently, with contracts generated from
schemas. The Phase 1C prompt asked for an explicit pnpm / Turborepo / Nx evaluation.

## Decision

- **Package manager: pnpm 9** (provisioned via Corepack). Workspaces declared in `pnpm-workspace.yaml`.
- **Build/task orchestration: Turborepo** (`turbo.json`) with caching for `codegen`, `typecheck`,
  `test`, `lint`, `validate:schemas`, `build`.
- **Language: TypeScript 5.7, strict ESM** (`"type": "module"`), `moduleResolution: "Bundler"`,
  `verbatimModuleSyntax`, `noUncheckedIndexedAccess`, `isolatedModules`. Shared base in
  `tsconfig.base.json`; each package extends it.
- **Internal package resolution:** workspace packages export `./src/index.ts` directly (these are
  internal, unpublished). Vitest and `tsc --noEmit` resolve TypeScript sources without a build step;
  bundling/emit (e.g. tsup) is deferred until a package needs to publish.
- **node-linker = hoisted** (`.npmrc`): a flat `node_modules` so shared dev tooling resolves from
  every package. Tradeoff: weaker isolation than pnpm's default symlinked store.
- **Schema → types:** `json-schema-to-typescript` generates `src/generated/` types from the canonical
  `schemas/*.schema.json`; `ajv` (Draft 2020-12) validates at runtime and in tests. Generated types
  are git-ignored and regenerated by `pnpm codegen`.
- **Testing: Vitest 2** (node environment, explicit imports — no globals). Conformance/contract tests
  live beside each package.
- **Lint/format: ESLint 9 flat config + typescript-eslint 8** (non-type-aware, fast) and **Prettier 3**.
- **Commit hygiene: Husky 9 + lint-staged + commitlint** (Conventional Commits; scopes = package/domain).
- **CI: GitHub Actions** running codegen → schema validation → typecheck → test → lint → format check.

## Alternatives Considered

- **Nx** — richer task graph/generators, but heavier and more opinionated than needed for a
  contracts-first foundation. Revisit if generator-driven scaffolding becomes valuable.
- **npm workspaces** — zero extra tooling, but slower and weaker workspace ergonomics than pnpm.
  Retained mentally as the fallback if pnpm/Corepack is unavailable in an environment.
- **pnpm default (symlinked) node-linker** — stronger isolation; deferred because shared dev tooling
  resolution across packages is simpler with a hoisted layout during the foundation phase.
- **tsc project references (composite)** — good for incremental emit, but adds ordering complexity.
  Deferred: the verification gate is `tsc --noEmit` + Vitest, which needs no build ordering.

## Consequences

- One command (`pnpm verify`) reproduces the full CI gate locally.
- Contracts cannot drift from types: types are generated from the canonical schemas, and schema
  validation runs against fixtures in CI ([ADR-0003](ADR-0003-tech-stack.md)).
- Adding a package = add a folder under `packages/*` with a `package.json`, `tsconfig.json`, `src/`,
  and tests; Turborepo and the workspace pick it up automatically.
- **Obligations / revisit:** restore stricter pnpm isolation and introduce `tsc -b` composite emit +
  bundling before any package is published externally; consider type-aware lint once project graph
  stabilizes.

## Open Questions

- Whether to adopt `tsup`/`unbuild` for publishable dist output, and when (driven by first external
  consumer or `services/` deployment).
